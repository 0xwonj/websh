# Read only browser implementation plan

Status: implemented; see [verification evidence and release blockers](progress.md).

Date: 2026-10-04. Baseline: `ce1d7a16cf1653baa80af71f90fcdf98178c755d`.

Implement the [read-only browser design](design.md), using the [removal inventory](removal-inventory.md) as a cross-crate checklist. Preserve wallet connection, viewing and terminal exploration, native publishing, and attestation behavior. Remove the two browser-authoring stacks and their shared support, then add a bounded external listing cache.

The phases are dependency-ordered work units, not commitments to deploy intermediate states. No release should claim read-only behavior until the complete removal phase and its negative capability tests pass. No cache release should precede the lifecycle and storage acceptance checks.

## Planning evidence and limits

The audit inspected current source, manifests, tests, runtime state, and the earlier snapshot note. It found two authoring entry paths, native-only uses of shared compose helpers, write-only administrator policy, and cache-related request races documented in the design.

The worktree already had untracked `AGENTS.md` and `dir_reference.html`; neither is generated by this plan. Local main was seven commits ahead of the verified GitHub main during the preceding project review. Preserve those commits and files; this task does not authorize replacing history or deploying them.

During the preceding review in this conversation, format, CSS lint, and docs drift checks passed. Rust tests were blocked at the host linker by an unaccepted Xcode license; WASM and E2E gates were not established. Treat that as an environment preflight item, not a code-test failure or permission to accept licensing terms automatically. That was the planning baseline; the user subsequently resolved the license prerequisite. Current test results are recorded in [progress](progress.md).

The checked items below describe completed implementation work, not release approval. The original release size was not captured, real-wallet signing was not exercised, and the dependency gate still reports two pre-existing unmaintained packages; see [the evidence and remaining release work](progress.md). Existing user browser profiles were not opened for draft inspection or recovery.

## Phase 1 Remove browser authoring as a complete vertical change

This is the largest coherent removal. Its substeps may be developed incrementally, but they form one integration boundary: no final dormant writer subsystem or compatibility writer feature flag remains.

### Remove consumers and entry points

- [x] Remove `/new` composition routing, reader editing modes/toolbar/shortcuts, `raw_source` editor seeding, and direct mempool saves.
- [x] Remove PAT forms, author mode, submit controls, editor modal, dirty/saving UI, and their CSS.
- [x] Remove mutation commands, staging effects, `sync` parsing/completion/help, and browser handlers.
- [x] Introduce `refresh [path]` as read behavior, initially using the existing read reload services. Keep wallet login/logout and all retained viewer actions.
- [x] Make `echo` treat `>` and `>>` as literal arguments. Remove redirection model/side effects.
- [x] Install the narrow retired credential-command guard before echo/history. Do not retain token APIs to implement it.

### Remove state and common writer code

- [x] Delete draft boot effects, `drafts.rs`, old `storage_state.rs`, old IDB module exports, editor state, commit heads, and token state.
- [x] Delete `ChangeSet` and filesystem merge, runtime commit engine, commit DTOs/methods/errors, and browser GraphQL transport.
- [x] Make components consume the content filesystem directly; retain a synthetic system view for environment/wallet/session files.
- [x] Rename synthetic `pending_text` storage to inline-text terminology. Remove write-only update/export helpers with no retained caller.
- [x] Remove access policy/administrator allowlist and writable permission computation while preserving wallet values and advisory recipient read display.
- [x] Remove writable fields and CLI `--writable` output/option. Accept legacy extra JSON fields without mapping them into capabilities.
- [x] Stop supplying `EDITOR` as a default. Remove the exact retired token sessionStorage key best effort; leave wallet and preference keys intact.
- [x] Keep CLI-used compose/serialization/frontmatter helpers and native Git/GitHub adapters. Remove browser-only placeholder/new-path helpers and obsolete CLI/browser guidance.
- [x] Remove direct browser `base64` and unused imports/features after checking all targets. Keep `idb`/serialization dependencies for the upcoming cache or add them back in Phase 3 if temporarily unused.

### Update tests and gates with the removal

- [x] Replace authoring E2E tests with absence-of-authoring and wallet-preservation cases. Keep independent reader and mempool assertions.
- [x] Delete commit integration target/tests and the obsolete gate in `justfile` and verification docs. Remove the `mock` feature only if all its remaining consumers have been replaced by read test doubles.
- [x] Update source mount config and fixtures, then regenerate generated artifacts through their owning commands.
- [x] Update help and current architecture statements for the implemented removal. Do not document the cache as implemented yet.

Exit: all R and W acceptance rows below pass; native publishing checks pass; explicit native and WASM compilation succeeds. The browser can load and refresh public content without opening either the old authoring DB or the not-yet-implemented cache DB.

## Phase 2 Establish read refresh correctness

- [x] Replace load/write-gating states with availability plus refresh status; keep epoch and content revision on each mount entry.
- [x] Allocate a root request sequence at dispatch; keep installed runtime generation separate. Gate stale root success and failure, preserving the installed runtime during a refresh.
- [x] Preserve available external trees during refresh/failure. Remove `allow_missing_manifest`; accept an empty tree only from a valid empty manifest.
- [x] Construct replacement trees off the published state and atomically publish successful assembly/status. Preserve failed declaration boundaries and unrelated mounts.
- [x] Route unresolved external deep links using owning mount availability. Keep normal root and bundle/locale behavior.
- [x] Add per-mount content revisions to text/inflight keys and reader resources, advancing only on accepted snapshot publication. Preserve loaded bodies during refresh/failure. Guard text, binary, and ledger-prefetch completions; release replaced object URLs.
- [x] Apply a 10-second deadline to manifest response-body retrieval, with best-effort abort and late-result guards. The current generic fetch helper only times out waiting for headers; do not assume it already covers the whole operation.
- [x] Connect terminal `refresh` and failure-panel retry to the same coordinator. Do not add another implicit polling subsystem.

Exit: lifecycle tests pass using deterministic read backends with controllable completion order, without requiring IndexedDB. Current content remains readable during refresh, and old results cannot overwrite newer work.

## Phase 3 Implement disposable cache storage

- [x] Add browser-runtime cache descriptor, deterministic key encoding, record validation, and an injectable cache capability.
- [x] Add `websh-cache` v1 and its single `mount_snapshots` store. No `websh-state` opening, migration, or deletion code enters the new production path.
- [x] Reuse manifest serialization/parsing for round trips, preserving bundles, empty directories, access metadata, and mempool extensions.
- [x] Implement the 500 ms restore and 2-second other-operation deadlines, including connection open and transactions. Abort timed-out transactions best effort, ignore late callbacks, release writer queues, and clean up late-open connections. Handle `versionchange`, blocked opens, and version errors without blocking reads.
- [x] Implement whole-record atomic compare/put/prune transactions, await transaction completion, and keep unrelated asynchronous work outside the transaction.
- [x] Apply the design's count, byte, age, timestamp, and per-record limits. Oversized live records remain readable without persistence.
- [x] Implement per-key write serialization/coalescing and timestamp ordering across tabs. Validate existing records before ordering; invalid/expired records cannot prevent replacement. Recheck records inside cleanup transactions. Check current request identity before scheduling persistence.
- [x] Handle quota with one bounded eviction/retry; disable persistent writes for the session if it fails. Other storage failures become cache misses, never root failures.

Exit: all I acceptance rows pass in a real browser. Storage tests prove the old database and wallet/preferences are untouched, and transaction abort does not destroy a prior good record.

## Phase 4 Integrate cache restore and refresh UX

- [x] Enforce the 500 ms restore deadline. Coordinate early network failure with a pending bounded cache lookup.
- [x] Accept a cache hit only for the current source/generation/epoch before live success and while no snapshot is installed for that attempt. Late cache results have no effect.
- [x] Persist only validated live snapshots that were successfully published, using the original backend scan before global assembly.
- [x] Build all derived routes/views through the existing manifest/routing logic. Do not persist a separate route index or a wallet-filtered tree.

- [x] Preserve root/home responsiveness, mempool counts/filtering, external direct links, locale bundles, and path-gateway hash URLs.
- [x] Confirm wallet account changes update current identity/advisory display without repartitioning public cache records.

## Legacy data recovery and retirement

Production simplification and deletion of user-authored data are different operations. The new app must not need the old database, but it also must not destroy it automatically.

Before a user chooses to remove old data:

1. Use the same browser profile and exact site origin where editing occurred. Other origins/devices have separate storage.
2. Close or reload old application tabs so they stop autosaving/recreating state.
3. Inspect `websh-state` through browser developer tools. If recovery is needed, use a one-off read-only export of existing raw object-store records, without a requested newer DB version. Abort any unexpected database-creation/upgrade event. Do not call the old application's `open_db()`.
4. Preserve records from `draft_changes`, `metadata`, and an older `drafts` store if present. Keep keys and raw values; do not depend on deleted Rust types to interpret/export them. Save the export locally, with no upload.
5. Confirm the export is usable or that no draft data is needed before manually deleting `websh-state`. Avoid “clear all site data,” which also removes retained wallet/preferences/cache state.

Do not ship a legacy draft reader, migration pipeline, export modal, or authoring compatibility mode in the website. A recovery note or one-off maintenance helper is sufficient if recovery is actually needed. Discarded commit-head metadata is not converted into listing cache data. The new cache is rebuildable and may be cleared independently.

Classify every remaining match. Tests of retired syntax, deliberate exact-key cleanup, legacy declaration fixtures, and unrelated names may remain; production writer capabilities may not. Inspect wasm-specific paths explicitly. A native build alone cannot establish browser correctness.

Manual smoke sequence after automated checks: connect wallet, inspect prompt and wallet menu, browse root and ledger, open a mempool item, switch language/theme, refresh its mount, then reload with the external mount endpoint unavailable after a successful cache population while the application shell and root remain available. Retry when that endpoint returns, and verify the connected wallet still cannot author content. Separately confirm that complete network loss or a cold root failure is reported honestly, without a full offline-startup claim. Repeat essential read flows with IDB disabled. Keep all remote writes fixture-backed.

## Deferred work and non goals

This plan does not implement full offline file reading, private mounts, encryption/access control, new IPFS/ENS adapters, service-worker application caching, cross-tab UI synchronization, automatic background polling, cache management screens, remote HEAD pinning, or a new local authoring tool. It does not remove the terminal, mempool, wallet, native authoring, or attestation pipeline.

Future cache policy tuning may change the explicitly documented limits after measurement. It must not reintroduce draft storage or remote write protocols into the browser.
